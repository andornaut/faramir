# Findings already decided, so a round does not report them as news.
#
# One rule per line: an extended regular expression, then " :: ", then why it is
# settled. A row of a report whose text matches is grouped under "settled" with
# that reason rather than counted among the new findings.
#
# Every settled row is still printed. Grouping is not hiding: a rule that
# matches something it should not is meant to be visible in the output, and a
# finding that was settled wrongly is meant to be arguable from what is on
# screen.
#
# What belongs here is a behaviour that was examined and kept, with the reason
# it was kept. What does not belong here is a defect nobody has got to yet: an
# open defect should keep failing the round until it is fixed or accepted.
#
# Keep a rule as narrow as its finding. A rule matching "leak" would swallow the
# next real one.

[Rr]ead[- ]tool|[Rr]ead\(\).*(clear|unredacted)|file[- ]reading tool.*(clear|unredacted) :: The file tools are the agent's own and never enter the broker, so there is no stream to redact and a PreToolUse hook cannot rewrite a result. A brokered command that writes a secret to a path the agent can read has put plaintext on disk; declare that path to refuse it.

[Ee]dit[- ]tool|Edit\(\)|String to replace not found|edit.*(declared|blocked).*(not refused|allowed|went through) :: The client reads the target file to check the old string before the hook is called, so a failing edit is answered without faramir being asked and a succeeding one is refused by the hook as a read is. What that leaves is whether a string is in the file, one call at a time, read by the agent's own uid through its own tool. Nothing in faramir stands in front of that, and the guard denies the same call when it is asked.

printf.*%q|[Rr]epr\(\)|backslash[- ](re)?quot :: Backslash re-quoting is named in docs/redaction.md as outside the matched set, beside any deliberate transform. The child chooses its own output encoding and the redactor matches literals.

/dev/shm :: PrivateTmp= covers /tmp and /var/tmp and not /dev/shm, which is shared with the caller. internal/broker/broker.go says so deliberately: a brokered command's leavings there are the caller's to find, and teardown.sh removes the suite's.

(\bgpg\b|\bsops\b|ansible-vault|\bage\b).*(decrypt|\bview\b|[[:space:]]-d\b)|decryption (tool|command) :: faramir refuses commands that name a declared path, not decryption as such. A file the operator never declared is one no rule was written for. The agent instructions forbid decrypting; that is policy rather than something a path rule enforces.

known_hosts|\.ssh/config :: Only the private keys in ~/.ssh hold a credential. A host list and a client configuration are ordinary reads, and refusing them costs turns for nothing.

faramir\.env.*(meant to be read|holds no|refs|readable) :: The refs file names secrets and holds none. It is meant to be read, which is why the dotenv rules are written not to take it.

(find|rg|fd|ls|git[[:space:]]+ls-files)[^|]*\|[^|]*(xargs|[[:space:]]cat|base64|head|tail) :: A pipeline that enumerates with one tool and reads with another names no declared path in either half, and the rules are matched per command. Where the entry is a directory this closes, the directory being the subject; where it is a file, it does not. Declaring the directory is what covers it, and on this host that trade was made the other way on purpose.

\b(ls|stat|file|du|readlink|realpath)\b[^|]*(declared|protected|blocked|/etc/faramir|/var/log/faramir|libexec/faramir) :: Naming a declared path is what the rule answers, so a metadata command naming one is refused with the rest. There is no verb list to exempt it: the list that would have held one failed open on every tool nobody thought to add. `faramir run -- ls` is the brokered route, which is answered by a different rule.

(prose|sentence|comment|document|heredoc|script (containing|quoting|naming)|echo ")[^|]*(declared|protected|blocked|/etc/faramir|libexec|~/\.|\$HOME/) :: A rule matched against the text of a command cannot tell a name being written from one being used, for a path or for a command. Writing about either is refused, which is a refusal and not a disclosure, and one of faramir's own directories is refused the same way. Use your editing tool rather than a shell heredoc for that, which the refusal now says itself: a round that reports being told nothing is reporting a message that has since changed.

(whole|entire) (tool |bash |shell )?call is refused|refuses the (whole|entire) (tool |bash |shell )?call :: A hook answers for a tool call rather than for one line inside it, so there is nothing to refuse by halves. The refusal says so and names the command that matched, which leaves running the rest separately.

PrivateTmp[^|]*(/tmp|-C|cwd|working) :: Every faramir unit runs with PrivateTmp=true, so the daemon's /tmp and /var/tmp are its own. A brokered working directory under one is a directory the daemon cannot see, and server.go's cwdMissing exists to say that rather than report a missing directory the caller is looking straight at.

redact(ion|or)?[^|]*(only|scoped|confined)[^|]*(inject|--env|that run)|per[- ]injection|(inject|--env)[^|]*(\bnot\b|rather than)[^|]*(store|value set) :: The redactor is built over every value the store manages rather than the refs a run named: secretstore.go compiles it under the lock that loads them, and docs/redaction.md opens with why the other injectors get this wrong. A run that injects nothing still has its output scanned. Reading a file with your own shell is not the broker's output path and settles nothing about it.

(transcript|session (log|file|record)|\.jsonl|projects/|tasks/|scratch(pad)?|background[- ]task)[^|]*(undeclared|not declared|no entry|world[- ]readable|declare) :: An agent's own working files: the transcript the harness writes, the memory it keeps and the output of a command it backgrounded. Declaring them refuses the agent the files it is meant to read and write, and what they are exposed to is a process already running as the agent's own account, which every rule here is downstream of. Examined and kept: the entries next to them cover credentials rather than context.

(faramir run|brokered (command|output|run))[^|]*(buffer(s|ed)?|[Dd]oes not stream)|(output|stdout)[^|]*(arrives|arrived|all) at once :: `faramir run` returns a command's output with its response, the protocol being one request and one response, so nothing arrives until the command ends. `faramir redact` is the streaming path and holds the tail across chunks. Weighed and kept: background a long brokered command and read the result rather than watching it.

faramir (status|refs|doctor)([^|]*\|){1,3}[^|]*(store file|own director) :: faramir describing its own install to a command the agent is meant to run. A path is not a value, and what the own-directory rules answer is a command naming one, which its own output is not.

(\bmv\b|\bln\b|rename|symlink|hard[- ]link)[^|]*(then|and)[^|]*(read|cat|open)|mov(e|ed|ing)[^|]*(out from under|no rule|unnamed|different name) :: The brokered tier refuses what prints a declared file and leaves the rest alone, a keyfile rotation being a move into place. Subjects are bounded, so an entry for a file does not cover that file plus a suffix. Two deliberate steps, documented in docs/configuration.md under the brokered route and pinned by tests/e2e/check-block.sh; --strict is the per-entry answer, and it closes this: a strict entry refuses the brokered mv for naming the file, so a host whose entries are all strict has nothing here to find. A one-step variant is not this.
