# Bash commands the agent may not run, one RE2 regex per line. Blank lines and
# #-comments are ignored. Matched case-insensitively against the whole command
# string.
#
# Rendered at install against the layout, so an operator who moved the config
# and the store gets rules naming where they are. Interpolated paths go through
# regexQuote. The guard's built-in fallback carries the compiled defaults.
#
# Not the security boundary, the agent uid being unable to read the key material
# regardless, but a corrective message naming `faramir run` instead of an EACCES,
# and no encrypted blobs in the context window. See docs/design.md.
#
# It names credential disclosure plus writes to the paths that are the broker
# itself. It is not a general destruction guard.
#
# One limit: a pattern matches the command string, so a grep or a heredoc that
# only mentions the text is refused like one that would run it.
#
# A rule reaches a path in the command it started in and no further. What ends a
# command is not the pattern: the guard splits the line first, at a separator
# that is not inside quotes, so `head a.txt; echo "k"` is two commands and
# `python3 -c 'import os; open("k")'` is one. A pattern cannot read quoting, so
# a pattern is never given a whole line.

# No rule for a decryption verb, and none for another tool's secret store.
#
# `sops -d`, `age -d`, `ansible-vault view`, `op read`, `pass show` and the rest
# were compiled in here, and each was an opinion about a tool this install may
# have nothing to do with: sops is how faramir's own keeper decrypts, but a
# store somewhere else is somebody else's, and the age key an install mints is
# already refused by the directory holding it.
#
# A host that wants one says so, and gets it on the same terms as a path:
#
#     sudo faramir block add --command 'op read' --command 'sops -d'
#
# The words are literal and the whitespace between them is any run of it, so
# what an operator declares is what they would type.

# No rule for a wholesale environment dump. In an enrolled tree the command is
# rewritten before it runs, so `printenv` comes back with every managed value
# replaced by its token, which covers the case a pattern was for and covers it
# whatever printed it. What a pattern would add is the operator's own exported
# credentials, which faramir does not manage and cannot know the names of, and
# it would add nothing at all in a tree that was never enrolled, where no hook
# runs to apply it. A credential that must not reach this shell belongs outside
# the environment the agent inherits.

# The binary, named as one path rather than as its directory, or installing any
# unrelated tool into {{.BinDir}} would be refused.
{{marked "ownaction" (printf `%s%s%s/faramir\b` writeCommands argSpan (regexQuote .BinDir))}}
{{marked "ownaction" (printf `>\s*\S*%s/faramir\b` (regexQuote .BinDir))}}

# The plugin and extension an enrolment installs, which are faramir's own files
# rather than shared ones: init-project overwrites each in full on every run, so
# an edit here is discarded rather than kept, and what a removal buys in the
# meantime is an agent whose commands stop being routed through the guard.
#
# The merged files are deliberately absent: .claude/settings.json,
# opencode.json, kilo.json and the Antigravity CLI's settings carry the
# operator's own settings beside faramir's entries, which is why an install
# merges into them instead of replacing them. Editing those is
# ordinary work. What covers them instead is `faramir doctor`, which reports a
# registration that went missing, and the rule in the credentials section
# against removing faramir's own entries from a file you are otherwise free to
# change.
{{marked "ownaction" (printf `%s%s(opencode/plugin/faramir\.js|kilo/plugin/faramir\.js|pi/agent/extensions/faramir\.ts|codex/hooks\.json)` writeCommands argSpan)}}
{{marked "ownaction" `>\s*\S*(opencode/plugin/faramir\.js|kilo/plugin/faramir\.js|pi/agent/extensions/faramir\.ts|codex/hooks\.json)`}}

# Stopping or masking one of faramir's units, which is refused for what it costs
# rather than because it hides anything: the wrapper fails closed, so a stopped
# broker withholds every command's output in every enrolled tree at once.
#
# Here rather than below the operator commands: the kinds decide the order now,
# and this is faramir's own alongside the binary and the plugin files.
{{marked "ownaction" `\bsystemctl\b.*\b(stop|disable|mask|kill|edit)\b.*\bfaramir-`}}

# Reaching the broker's private state. Reading the audit log is covered above;
# listing the directory is not. journalctl is absent: the daemons log ref names
# and counts, never values.
#
# faramir under sudo, whichever subcommand: the daemons, the internal helpers,
# the escalation channel and every provisioning command at once. Nothing an
# agent may run needs root -- run, redact, status and `refs` all answer as
# the agent's own account -- so a sudo here is either a daemon, a decision that
# is the operator's, or a change to the install. Only sudo's own flags may
# precede the name. Managing a unit is not this, so "systemctl restart
# faramir-keeper" stays allowed; journalctl likewise, the daemons logging ref
# names and counts and never values.
{{marked "operator" `\bsudo\b(\s+-\S+)*\s+faramir\b`}}
# The same commands unprivileged. They act on the install rather than through
# it, so they are the operator's whether or not sudo is in front: refused here so
# the agent is told that, rather than meeting a permission error it will try to
# work around.
{{marked "operator" `\bfaramir[-\s]+(block[ \t]+add|block[ \t]+rm|init|init-project|link[ \t]+add|link[ \t]+rm|logs|reader[ \t]+add|reader[ \t]+reseal|reader[ \t]+rm|reload|sudo[ \t]+approve|sudo[ \t]+ls|sudo[ \t]+reject|sudo[ \t]+watch|uninstall|vault[ \t]+add|vault[ \t]+edit|vault[ \t]+ls|vault[ \t]+rm)\b`}}
{{marked "operator" `\bsudo\b.*-u\s+faramir`}}

# The broker's own key by path, not left to the config directory: `--ssh-key`
# may put it anywhere, and one placed outside that directory is named by no
# rule the layout renders.
#
# Here rather than above the action rules: it is an `own` rule, and
# denyrules.Kinds() puts own after ownaction and operator. Rendered ahead of
# them it would answer a command that matches both, and the broker, which holds
# the same rules in Kinds() order, would answer that command differently.
{{if .SSHKey}}{{ownRule .SSHKey}}
{{end}}
# Last, because a line can match this and a rule above it: an agent running a
# faramir subcommand against a declared path is told it is an operator command,
# which is the more useful of the two answers, and decide reports the first rule
# that matches. The order is denyrules.Kinds(), which the broker holds its own
# rules in as well, so neither tier answers such a command differently.
#
# No verb in front of them. A declared subject is an absolute path, and a path
# names itself: the vocabularies this replaced existed to tell a file access
# from prose while a subject could be a bare name. What they cost was a list
# that failed open, short of rg, fd and bat and of whatever ships next.
#
# One rule per kind of entry, each naming its kind in a group: `own` for a
# directory the install occupies, `blocked` for a [[secret.block]] path, and
# `linked` for a file a [[secret.link]] reads. The group matches what the rule
# matched and changes nothing about what is refused. It is there so the refusal
# can name the command that takes the entry back, which differs by kind and
# which one rule over all three could not say.
#
# Every line above carries one too, `ownaction` or `operator`, and a declared
# command carries `command`. A line that carried none was classified by matching
# a substring of itself, so how a rule was spelled decided which message it got.
{{range commandRules .}}{{.}}
{{end}}
