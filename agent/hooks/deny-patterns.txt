# Bash commands the agent may not run, one RE2 regex per line.
# Blank lines and #-comments are ignored.  Matched case-insensitively against
# the whole command string.
#
# Rendered at install against the layout, not copied: which paths are worth
# refusing belongs to an install rather than to this file, so an operator who
# moved the config and the store into a home gets rules naming where they
# actually are.  Interpolated paths go through regexQuote, because a path lands
# in a regex.  The guard's built-in fallback carries the compiled defaults for
# the case where this file cannot be read at all.
#
# This list is ergonomics with teeth, not the security boundary: the agent uid
# cannot read the key material regardless.  What it buys is that the agent gets
# a corrective message naming faramir_run instead of a confusing EACCES, and
# that encrypted blobs and env dumps stop polluting the context window.
#
# It names credential disclosure, plus writes to the few paths that are the
# broker itself: the store, the age keys, and this hook's own files.  It is not
# a general destruction guard.  Enrolling a project auto-approves Bash there, so
# whatever prompting stood between the agent and rm -rf is gone and this list
# does not replace it.  See docs/scope.md.
#
# Two limits.  A pattern matches the command string, so a command that only
# mentions the text -- a grep, a heredoc writing documentation about this
# project -- is refused exactly like one that would run it, and nothing here can
# tell them apart.  And "[^|]*" rather than ".*" wherever a rule spans
# arguments, so it stops at the first pipe instead of matching something
# harmless further along the line.

# Direct decryption of the secret store
ansible-vault\s+(view|decrypt|edit|rekey)
\bsops\s+(decrypt|-d|--decrypt|-i\s+.*-d)
# Writing the store is the operator's, for the same reason reading it is: the
# agent has no value to put in one and no way to check what it replaced.
\bsops\s+(-e|--encrypt|encrypt|set|unset|rotate|updatekeys)\b
\bage\s+(-d|--decrypt)
# Bare age-keygen prints a private key.  "-o FILE" writes it 0400 and prints
# nothing, which is how a throwaway key is minted, so only the printing form
# is refused.
\bage-keygen\b(\s+-\S+)*\s*$
\bop\s+read\b
\bpass\s+show\b
\bgopass\s+show\b
\bvault\s+(read|kv\s+get)\b

# Wholesale environment dumps.  "env NAME=value cmd" is ordinary shell rather
# than a dump, so the match ends after the flags; "env | grep FOO" narrows
# rather than dumps and ends the match too.  printenv stays broad on purpose:
# "printenv PATH" is harmless and "printenv ROUTER_PW" is not, and the rule
# cannot tell which name is a secret.
\bprintenv\b
# "env" must sit in command position.  "\benv\b" also matched a filename ending
# in .env, so naming one at the end of a line was refused as a dump.
(^|[\s;&|(])env(\s+-\S+)*\s*$
\bset\s*$
\bdeclare\s+-x\b
/proc/\d+/environ
/proc/self/environ

# Reading key material or encrypted blobs straight into the context window.
# The key names are spelled out: "id_[re]d?sa" looked like it covered SSH keys
# and matched id_rsa and id_dsa while missing id_ed25519, which is what
# ssh-keygen has produced by default for years.
# "sops/age" is the age key an agent can actually reach: faramir's own age key
# is keeper-owned 0400 wherever it sits, but the operator's
# ~/.config/sops/age/keys.txt decrypts the same store and is readable by the uid
# the agent runs as.  It matches none of the other alternatives, because the
# file is keys.txt and "age\.key" wants a literal dot.
#
# The reader list carries interpreters and copiers as well as pagers: reading a
# key with python, or copying it somewhere unmatched and reading it there, is
# the same disclosure.  "sed" stays out of this rule, because it edits far more
# often than it dumps; it appears in the write rule below instead, where the
# paths are faramir's own and touching them at all is wrong.  "grep" stays out
# so that naming a .env file in a search is not refused.
#
# "[\s/=]\.env" rather than "\.env", so a file merely ending in those four
# characters (faramir.env, which holds refs and no values) is not a dotenv.
\b(cat|less|more|head|tail|bat|xxd|od|strings|base64|base32|hexdump|uuencode|rev|tac|awk|cut|nl|dd|jq|yq|python3?|perl|ruby|tee|cp|tar|scp|rsync)\b[^|]*(vault|secrets?\.|[\s/=]\.env|age\.key|sops/age|id_(rsa|dsa|ecdsa|ed25519)|\.pem\b|credentials|\.faramir\b|{{.ConfigDir | regexQuote}}|{{.SecretsDir | regexQuote}}|{{.LogDir | regexQuote}})
\bfind\b.*-name.*(age\.key|\.env|id_(rsa|dsa|ecdsa|ed25519))

# Changing the broker's own files, rather than reading them.  The store is
# writable by the agent's uid, and so is anything under a home; the hook's
# patterns and binary decide what it refuses, so they are named here too.
#
# The redirect rule matches the target word only, not the rest of the line, so
# that a heredoc writing documentation that mentions one of these paths is not
# mistaken for a write to it.
\b(rm|shred|truncate|mv|cp|tee|dd|sed|chmod|chown|chgrp|setfacl|ln)\b[^|]*(age\.key|sops/age|\.faramir\b|{{.ConfigDir | regexQuote}}|{{.SecretsDir | regexQuote}}|{{.LibexecDir | regexQuote}}|\.sops\.ya?ml|\.vault\b)
>\s*\S*(age\.key|sops/age|\.faramir\b|{{.ConfigDir | regexQuote}}|{{.SecretsDir | regexQuote}}|{{.LibexecDir | regexQuote}}|\.sops\.ya?ml)

# Trying to reach the broker's private state.  Reading the audit log is covered
# by the rule above; listing the directory is not, and does not need to be.
# journalctl is deliberately absent: the daemons log ref names and counts,
# never values, and blocking it only stops the broker being debugged.
\bsudo\b(\s+-\S+)*\s+faramir-(broker|keeper|exec)\b
\bsudo\b.*-u\s+faramir
\bsystemctl\b.*\b(stop|disable|mask|kill|edit)\b.*\bfaramir-
